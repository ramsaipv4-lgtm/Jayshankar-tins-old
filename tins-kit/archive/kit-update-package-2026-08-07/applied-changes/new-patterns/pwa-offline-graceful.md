# `pwa-offline-graceful` — kit pattern

> **The canonical recipe for "make the app work offline" without
> building an offline write-queue.** Three layers: a hook, a banner, a
> form-level guard. Self-contained.
>
> **Source:** Jayshankar decisions 26 (PWA config) and 27 (offline
> detection). The "PWA + read-only offline" stance is SPEC D6, common
> to many TINS consumers (wholesale inventory, field inspections,
> inventory audits).

---

## 0. Why this exists

The instinct for offline support is to build a write-queue: store pending
mutations in IndexedDB, replay on reconnect, deduplicate by client ID.
This is a 1-2 week project and has subtle bugs (conflict resolution,
partial sync, lost updates).

For V1, the right answer is simpler: **read offline, write online.**
The app shows the last good read snapshot. Mutations are disabled when
offline. When the network returns, mutations re-enable. No queue, no
sync, no conflict resolution.

This pattern ships that minimum-viable offline experience in 3 files
and ~80 lines of code, with a service worker that caches the app shell
and the most recent API responses. It's a V1 deliverable; the
write-queue is a V2 upgrade (see "When this changes" at the end).

---

## 1. The 3 lessons, in detail

### Lesson 1 — Three layers, not one

| Layer | What it does | Why it's needed |
|---|---|---|
| `useOnlineStatus()` hook | Reads `navigator.onLine`, listens to `online`/`offline` events, returns a boolean. | Source of truth. One subscription, one state, all components re-render when it flips. |
| `<OfflineBanner />` | Renders an amber banner below the header when `online === false`. | The user signal. SPEC §3.5 says `role="status" aria-live="polite"` so screen readers announce without stealing focus. |
| Form-level guard | `if (!online) { setError(...); return; }` in `onSubmit`; `disabled={... || !online || ...}` on the submit button. | The safety net. Disabled is the primary defense; the inline error catches keyboard-shortcut or extension bypass. |

Why all three? A single layer has gaps:
- Hook only: components know offline, but the user has no visible cue.
- Banner only: the user knows offline, but the mutation form happily
  submits and the network call fails.
- Form only: the form blocks, but the rest of the page still tries to
  fetch and surfaces cryptic errors.

Belt and braces. The hook is the truth, the banner is the UX, the
form is the gate.

### Lesson 2 — `navigator.onLine` + window events, not a fetch heartbeat

The browser fires `online` and `offline` events on actual network state
changes (WiFi on, WiFi off, captive portal). The pattern listens:

```ts
useEffect(() => {
  const onOnline = () => setOnline(true);
  const onOffline = () => setOffline(false);
  window.addEventListener('online', onOnline);
  window.addEventListener('offline', onOffline);
  return () => {
    window.removeEventListener('online', onOnline);
    window.removeEventListener('offline', onOffline);
  };
}, []);
```

Why not a periodic fetch heartbeat?
- Costs an extra request every N seconds
- Has false positives (Supabase is down but the LAN is up)
- Has false negatives (the device is on a captive portal that allows
  some hosts)
- The event API is reliable; the heartbeat is a guess

### Lesson 3 — The PWA service worker is the safety net, not the primary
cache

The PWA service worker (Workbox, generated by `vite-plugin-pwa`) caches:
- The app shell (HTML, JS, CSS, SVG icons) — precached on install
- The last 24h of Supabase REST responses — runtime cached with
  `NetworkFirst` and 5s timeout

The primary cache is the in-memory React Query store. The SW is the
cross-restart safety net: if the user closes the tab and reopens
offline, the SW serves the last good reads. The 24h window is long
enough for a demo day, short enough that the cache doesn't go
embarrassingly stale.

NetworkFirst (not CacheFirst) means: when online, always serve the
freshest data. When offline (or the network takes >5s), fall back to
the cache. This is what "read-only offline" looks like in practice.

## 2. The recipe

### Step 1: install and configure `vite-plugin-pwa`

```bash
npm install -D vite-plugin-pwa
```

```ts
// vite.config.ts
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    react(),
    VitePWA({
      registerType: 'autoUpdate',
      devOptions: { enabled: true },  // see the SW in dev for testing
      includeAssets: ['favicon.svg', 'icon.svg'],
      manifest: {
        name: '<app name>',
        short_name: '<short>',
        theme_color: '#4f46e5',
        background_color: '#f8fafc',
        display: 'standalone',
        start_url: '/',
        scope: '/',
        icons: [
          { src: 'icon.svg', sizes: 'any', type: 'image/svg+xml', purpose: 'any maskable' },
        ],
      },
      workbox: {
        globPatterns: ['**/*.{js,css,html,svg,woff2}'],
        navigateFallback: '/index.html',  // hash-router deep links
        runtimeCaching: [
          {
            urlPattern: ({ url }) => url.host.endsWith('.supabase.co'),
            handler: 'NetworkFirst',
            options: {
              cacheName: 'supabase-api',
              networkTimeoutSeconds: 5,
              expiration: { maxEntries: 200, maxAgeSeconds: 60 * 60 * 24 },
              cacheableResponse: { statuses: [0, 200] },
            },
          },
        ],
      },
    }),
  ],
});
```

### Step 2: the online-status hook

```ts
// src/lib/online.ts
import { useEffect, useState } from 'react';

export function useOnlineStatus(): boolean {
  const [online, setOnline] = useState<boolean>(() =>
    typeof navigator !== 'undefined' ? navigator.onLine : true
  );
  useEffect(() => {
    const onOnline = () => setOnline(true);
    const onOffline = () => setOnline(false);
    window.addEventListener('online', onOnline);
    window.addEventListener('offline', onOffline);
    return () => {
      window.removeEventListener('online', onOnline);
      window.removeEventListener('offline', onOffline);
    };
  }, []);
  return online;
}
```

### Step 3: the offline banner

```tsx
// src/components/OfflineBanner.tsx
import { useOnlineStatus } from '../lib/online';

export default function OfflineBanner() {
  const online = useOnlineStatus();
  if (online) return null;  // no DOM, no layout shift when online
  return (
    <div
      role="status"
      aria-live="polite"
      className="bg-amber-100 border-b border-amber-200 text-amber-900 text-sm"
    >
      <div className="max-w-6xl mx-auto px-4 py-2 flex items-center gap-2">
        <span aria-hidden="true">⚠️</span>
        <span>Offline — read only. Changes will be available when back online.</span>
      </div>
    </div>
  );
}
```

### Step 4: wire the banner into the layout

```tsx
// src/components/Layout.tsx
import OfflineBanner from './OfflineBanner';

export default function Layout({ user, children }) {
  return (
    <div className="min-h-full bg-slate-50">
      <OfflineBanner />
      <header>...</header>
      <main>{children}</main>
    </div>
  );
}
```

### Step 5: form-level guard (apply to every mutation form)

```tsx
// src/pages/SomeMutationForm.tsx
import { useOnlineStatus } from '../lib/online';

export default function SomeMutationForm() {
  const online = useOnlineStatus();
  const [error, setError] = useState<string | null>(null);

  async function onSubmit(e: FormEvent) {
    e.preventDefault();
    if (!online) {
      setError('You are offline. Reconnect to record changes.');
      return;
    }
    // ... do the mutation
  }

  return (
    <form onSubmit={onSubmit}>
      {/* ... fields ... */}
      {error && <p className="text-red-600 text-sm">{error}</p>}
      <button
        type="submit"
        disabled={!online || /* other validity */ submitting}
        className="..."
      >
        Submit
      </button>
    </form>
  );
}
```

### Step 6: the icon

```svg
<!-- public/icon.svg (an SVG icon, maskable-safe) -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512">
  <rect width="512" height="512" rx="96" ry="96" fill="#4f46e5"/>

```

Reference it from `index.html`:
```html

```

### Step 7: validator checks (optional but recommended)

```js
// scripts/validate.mjs
const jsPwaOffline = {
  name: 'js-pwa-offline-banner',
  check(content) {
    if (!/vite-plugin-pwa/.test(readFile('package.json'))) {
      return 'vite-plugin-pwa missing from package.json';
    }
    if (!/useOnlineStatus/.test(readFile('src/lib/online.ts'))) {
      return 'useOnlineStatus hook missing';
    }
    if (!/Offline — read only/.test(readFile('src/components/OfflineBanner.tsx'))) {
      return 'OfflineBanner text not matching SPEC §2.14';
    }
    return null;
  },
};
```

## 3. The end-to-end flow (what the user does)

1. **Install `vite-plugin-pwa`.** Configure per Step 1.
2. **Add the icon.** `public/icon.svg`, maskable-safe, app-themed.
3. **Add the 3 files:** `online.ts` (hook), `OfflineBanner.tsx` (banner),
   wire into `Layout.tsx`.
4. **Update every mutation form** to import the hook, disable submit on
   offline, set the inline error in `onSubmit`.
5. **Test:**
   - DevTools → Application → Service Workers: SW is `activated and is running`.
   - DevTools → Application → Manifest: no warnings, the icon loads.
   - DevTools → Network → Offline: banner appears within 5s, submit
     buttons disable, error message appears on attempted submit.
   - Network back online: banner disappears within 5s, submit re-enables.
6. **Pin with a validator check** (optional). Future contributors can't
   remove the banner or the hook without failing the gate.

## 4. When this changes (V2 upgrades)

- **Offline write-queue.** The hook grows a richer shape:
  `{ online: boolean, pending: number, lastSync: Date | null }`. The
  banner grows a "syncing" state. The form guard grows an outbox enqueue
  path. The whole pattern evolves from "read-only offline" to
  "read-write offline, sync on reconnect." This is a 1-2 week project;
  defer until there's evidence the user actually needs it (Jayshankar
  decision 26 calls this out explicitly).
- **iOS / iPadOS support.** iOS Safari needs `apple-touch-icon-180x180.png`
  + `apple-touch-icon-152x152.png` and `<link rel="apple-touch-icon">` in
  `index.html`. The SVG-with-`sizes="any"` trick works on Android but
  not on iOS. Jayshankar is iOS-locked-out (SPEC D13); most TINS
  consumers should follow the same stance in V1.
- **Per-resource cache TTLs.** The 24h `maxAgeSeconds` is a single
  global. In production, you'd want 5min for the audit log, 1h for
  batches, 24h for the SKU list. Workbox supports multiple
  `runtimeCaching` rules.
- **"Back online" toast.** When the network returns, the banner just
  disappears. Adding a 3-second toast ("Back online. Changes will save
  again.") is a small UX win. Optional polish.
